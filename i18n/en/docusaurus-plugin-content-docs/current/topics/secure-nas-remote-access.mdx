# Secure NAS Remote Access Without Public Port Exposure

Home and studio NAS units store irreplaceable photos, personal documents, backups, and self-hosted apps—yet most residential broadband connections sit behind CGNAT with no public IPv4 address. Even when a public IP is available, forwarding NAS admin ports (`5000`/`5001`), SMB (`445`), or SSH (`22`) directly to the internet turns your storage box into a constant target for ransomware scanners and credential-stuffing bots.

Larktun eliminates port forwarding and DDNS completely. Instead of exposing your NAS to the public internet, Larktun places your NAS, laptop, and phone into an encrypted, identity-verified private mesh where only explicitly authorized devices can reach NAS services.

## Why Private Mesh Beats Port Forwarding and Vendor Cloud Relays

- **Zero public attack surface**: Your NAS admin UI, Docker containers, and SMB/WebDAV services never appear on Shodan or internet port scans.
- **Works seamlessly behind CGNAT**: No public IPv4 address, router UPnP, or fragile DDNS updates required.
- **Direct P2P speeds whenever possible**: Unlike vendor quick-connect relays that throttle every transfer through remote servers, Larktun negotiates encrypted peer-to-peer tunnels first and falls back to relays only when NAT requires it.
- **Granular port and user governance**: Separate full admin access (for you) from photo/media-only access (for family members) using tenant ACLs.

## Example: Least-Privilege ACL for Home NAS

After your NAS (or LAN subnet router) is online, avoid leaving every port open permanently. Scope ACL rules to the exact services you use—for example DSM HTTPS (`5001`), Immich/Photo Web UI (`2283`), and SMB (`445`):

```json
{
  "hosts": {
    "home-nas": "100.64.0.20/32"
  },
  "acls": [
    {
      "action": "accept",
      "src": ["owner@example.com@"],
      "dst": ["home-nas:5001", "home-nas:445", "home-nas:2283", "home-nas:22"]
    },
    {
      "action": "accept",
      "src": ["family@example.com@"],
      "dst": ["home-nas:2283"]
    }
  ]
}
```

With this policy in place, family devices can browse the photo library on port `2283` without ever being able to reach the NAS admin panel or SSH.

## Mobile Access Without System VPN Conflicts

On iPhone, iPad, or Android, you can open your NAS Web UI (`https://100.64.0.20:5001`), inspect files over SFTP, or check device latency directly inside the Larktun mobile app—without turning on a system-wide VPN or interrupting your work VPN.

## Quick Verification Checklist

1. Confirm the NAS (or subnet router) appears **Online** in **Nodes**.
2. Disconnect your phone from home Wi-Fi (switch to 4G/5G) and open the NAS admin URL using its private Larktun IP or LAN subnet IP.
3. Verify your router has **no** inbound port-forwarding rules pointing to the NAS.
