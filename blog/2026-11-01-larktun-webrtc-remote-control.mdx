出门后才想起，文件还在家里的电脑上。办公室的任务跑了一下午，想看看进度。家人遇到一个设置问题，电话里说了半天，还是不如自己点两下。

这些时候，我们需要的其实很简单：拿起手边的手机或平板，回到那台熟悉的电脑，接着处理眼前的事。

**云雀通 Larktun WebRTC 远程控制现已结束 Beta 测试，正式上线。** 电脑端体积小、没有广告，当前支持 **Windows 和 macOS 被控端**；配合 **iPhone、iPad 上的 Larktun App**，就能通过自己的云雀通网络，远程访问家里或办公室的电脑。

这次正式上线，我们想把一件事做好：让远程控制成为日常随手可用的能力。

## 轻量、无广告，装好就是自己的远控入口

远控经常只是一个几分钟的临时任务：改一处配置、看一个窗口、操作某个只能在电脑上运行的软件。为此安装一个程序，我们希望它足够小，也足够安静。

Larktun WebRTC Host 就是电脑上负责接收远程连接的被控端。**安装包轻量，使用过程中没有广告**，把重点放在屏幕、声音和操作本身。

Windows 提供安装向导，安装后以服务运行，支持开机自启。Mac 提供 `.pkg` 安装包，安装后通过菜单栏里的 **Larktun Host** 管理连接设置、系统权限和登录时启动。日常使用不必开着终端，也不必自己搭建一套屏幕采集工具。

电脑接入云雀通网络，Host 运行起来，手机上的远控入口就有了可以回去的地方。

## iPhone 随身处理，iPad 坐下来继续工作

手机一直在身边，是处理临时任务最方便的入口。

在 Larktun iOS App 中打开 **WebRTC 远控**，连接目标电脑，就能看到电脑当前的桌面，使用触控、屏幕键盘和快捷键进行操作。出门查看渲染进度、临时修改文档、帮助家人调整设置，都可以从手机开始。

需要多做一会儿时，换到 iPad。更大的画面，配合外接键盘、鼠标或触控板，让选中文本、切换窗口和输入内容更顺手；支持的 iPad 还可以把远程画面放到外接显示器上，在平板上保留触控操作区。

**程序和工作现场仍然留在远端电脑上。** 你看到的是它正在使用的桌面：已经打开的窗口、正在运行的软件、做到一半的任务，都可以接着处理。

App 内的组网能力不占用系统 VPN 权限。关于这一设计和其他移动端能力，可以继续阅读 [iOS 客户端能力概览](/docs/introduction/ios-app-overview)。

## 多台设备，同时连接一台电脑

这是一项很适合日常使用的能力：**一台电脑可以同时接受多台设备的远控连接。**

比如 iPad 已经连着办公室电脑，这时拿起 iPhone，也可以连接同一台电脑。或者你在演示一个操作，另一台已获授权的设备可以一起看同一个桌面。

为了让操作保持清楚，当前规则是：

- 多台设备可以同时观看同一桌面。
- 同一时刻由一台设备发送键鼠输入，其余设备显示为“仅观看”。
- 新设备首次加入时获得控制权，原来的控制端继续观看。
- 观看端点击 **“接管控制”**，就可以接手操作。

这样，从手机换到平板时，不必先手动断开上一台设备；多人协助时，也能看清当前是谁在操作。

多台设备共享的是电脑的同一个桌面。窗口变化、显示器切换和操作结果都会一起看到，适合设备切换、共同排错和操作演示。

## 画面之外，声音和操作也一起带过来

远程桌面要好用，还得照顾那些容易被忽略的小事。

**系统声音。** 开启声音采集后，电脑上的播放声音可以传到客户端，查看视频或确认软件提示时更方便。

**文本剪贴板。** 支持在手机、平板与电脑之间同步文本，复制一段地址、粘贴一条命令，少一次来回输入。

**多显示器切换。** 电脑连接了多块屏幕，可以在客户端选择要看的显示器；一次显示一块屏幕，操作跟随当前画面。

**画质设置。** 可以根据当前网络调整画质与帧率。在移动网络下优先让操作顺畅，网络充裕时再选择更清晰的画面。原生被控端使用 H.264 硬件编码路径，iOS 端使用硬件解码，让桌面串流更高效。

实际流畅度仍取决于电脑性能、上行带宽、延迟和连接路径。外出前试一次常用的网络环境，比只看一个画质参数更有帮助。

## 远控走自己的云雀通网络，隐私边界更清楚

远程控制会传输桌面内容，也允许对电脑发出操作，所以连接方式和访问范围都很重要。

Larktun 把 WebRTC 远控放在云雀通私有网络之上。手机先通过自己的网络访问目标，再由 Host 建立远控会话；屏幕、声音和控制消息都经由这条网络路径传输。

在这套用法下，**不需要把电脑的远控端口映射到公网**，也不必为了外出访问另行申请公网 IP 或配置 DDNS。哪些设备能访问目标，可以结合云雀通的网络权限和 ACL 管理，Host 还支持设置访问令牌。

网络条件允许时优先直连；受 NAT 或网络策略限制时，也可能使用中继。媒体和控制通道保持 WebRTC 加密，底层云雀通链路也提供加密保护。隐私保护来自加密与访问控制共同作用。

建议为 Host 配置访问令牌，并把监听范围和防火墙规则限制在需要的私有网络内。界面允许留空令牌，但日常使用时应主动设置。多设备协作时，也只让你愿意向其展示桌面、交出控制权的设备接入。

## 从家里到办公室，几个随手就能用的场景

**出门后补一件小事。** 文件留在电脑上，或者某个桌面软件需要点一次确认，打开 iPhone 就能回到原来的窗口里处理。

**随时查看长任务。** 渲染、导出、编译或数据处理还在跑，用手机看一眼桌面上的进度和报错，决定是否需要继续操作。

**轻装出行，继续使用自己的电脑。** 带上 iPad 和键盘，连接办公室的 Windows 或家里的 Mac，使用已经配置好的软件和环境。

**一起排查问题。** 两台设备连接同一桌面，一台操作、一台观看，需要时接管控制，减少来回描述“你现在看到哪个窗口”。

这些场景的前提是目标电脑在线、Host 正在运行，并且网络允许访问。准备长期在外使用时，记得提前检查电脑的睡眠和供电设置。

## 几步开始第一次连接

1. **下载并接入网络。** 从 [云雀通下载页](https://larktun.com/download) 获取电脑端与 iOS App，让目标电脑和手机接入自己的云雀通网络，确认设备在线、权限允许访问。
2. **安装 WebRTC 被控端。** Windows 运行 Host 安装向导，Mac 安装 Larktun Host，设置访问令牌并启动服务。
3. **完成系统授权。** Mac 需要允许“屏幕录制”和“辅助功能”，分别用于传输画面与执行输入；按 Host 提示完成授权和重启。
4. **在 App 中连接。** 打开“WebRTC 远控”，填写电脑的云雀通地址、Host 端口和相同的令牌。默认端口为 `8771`，修改过则使用实际值。
5. **保存常用入口。** 可以保存为收藏，之后从收藏进入；令牌保存在 iOS 系统 Keychain 中。

第一次连接建议先在身边完成，确认画面、声音和输入正常，再用手机的移动网络连接一次。这样出门之后就能直接使用。

## 几个你可能关心的问题

### Windows 和 Mac 都能被远程控制吗？

可以。当前正式版提供 Windows 和 macOS 被控端，iPhone/iPad 通过 Larktun App 发起连接。**全平台覆盖是后续方向**，其他平台的 WebRTC 支持请以之后的发布为准。

### 电脑锁屏后还能连接吗？

Windows 的服务化被控端支持锁屏、登录界面和 UAC 场景。Mac 在用户已登录后锁屏，可以远程操作解锁；重启后还没有首次登录时，暂时无法通过 Host 获取登录画面。计划无人值守使用时，先确认目标电脑上的实际表现。

### 已经有 RDP，为什么还需要 WebRTC？

WebRTC 远控直接连接 Host 采集的电脑当前桌面，适合接着操作本机已有窗口、共同查看同一现场，以及远控 Mac。Larktun App 同时保留 RDP、SSH 和内置浏览器，按任务选择入口就好。

### 能连上却没有画面，或者画面能看但不能操作？

先确认 Host 正在运行、地址与令牌一致，并检查网络权限。Mac 上分别检查屏幕录制和辅助功能授权；多设备连接时，看看当前是否处于“仅观看”，需要操作就点“接管控制”。一般网络问题也可以参考 [常见问题处理](/docs/troubleshooting/common-issues)。
