# Relationship Between Larktun, Tailscale, and Headscale

One of the first technical questions engineers ask when evaluating Larktun is: **how exactly does Larktun relate to Tailscale and Headscale?**

In short: Larktun is an independent SaaS zero-trust networking platform built with deep respect for the protocol and open-source ecosystem pioneered by **Tailscale** and **Headscale**, combined with extensive multi-tenant control-plane engineering, a custom SaaS console, and purpose-built desktop and mobile applications.

## How the Three Fit Together

| Layer | Tailscale | Headscale | Larktun |
|---|---|---|---|
| Data plane | WireGuard encrypted mesh + NAT traversal + DERP | Uses Tailscale clients' WireGuard data plane | WireGuard encrypted mesh + direct P2P + shared/dedicated/custom DERP |
| Control plane | Closed-source Tailscale SaaS | Open-source single-tenant Go control plane | Multi-tenant, clustered Headscale-derived SaaS control plane |
| Management UI | Tailscale Admin Console | CLI-first (third-party community UIs) | Custom SaaS console (Nodes, Routers, visual + JSON ACLs, Derper, Audit) |
| Client ecosystem | Official Tailscale clients | Official Tailscale clients | Custom Larktun clients (Desktop, Linux, OpenWrt, NoVPN iOS/Android/TV) + compatible with Tailscale clients |

## What Each Project Contributes

- **Tailscale** established the modern WireGuard mesh model: automatic key distribution, NAT traversal, MagicDNS, subnet routers, exit nodes, and declarative ACLs—making private networking dramatically simpler than legacy hub-and-spoke VPNs.
- **Headscale** proved that the control plane can be implemented transparently in open source, enabling developers to inspect and extend node registration, routing, ACL compilation, and MagicDNS.
- **Larktun** turns that foundation into a ready-to-use SaaS service and client suite without forcing every user to self-host servers, manage certificates, or wrestle with system VPN limits on mobile.

## What Larktun Builds on Top

Larktun is not a thin skin over a default Headscale binary. Key engineering investments include:

1. **True multi-tenant Headscale control plane**: Isolated per-tenant tailnets, custom IP pools (e.g. `192.168.6.0/24`), tenant-scoped ACL compilation, scoped MagicDNS (`hostname.<tenant>.<domain>`), and horizontal `cluster_id` sharding (detailed in our [Multi-Tenant Isolation](/blog/headscale-multi-tenant-isolation) and [Cluster Architecture](/blog/headscale-cluster-infinite-scale) engineering posts).
2. **Chinese & Unicode device aliases**: Readable device naming synced across the console and desktop/mobile clients so operators can recognize machines instantly.
3. **Independently developed NoVPN iOS/iPadOS & Android apps**: Powered by `tsnet` so users get Ping, SSH, SFTP, private Web browsing, RDP, WebRTC remote control, and AI assistant tools inside one app without occupying the OS VPN slot.
4. **Open-source contributions**: We publish our enhanced Android client, Headscale SaaS reference projects, and stress-testing scripts publicly for community review (see [Open Source Links](../introduction/open-source-links)).
5. **Managed SaaS console & relay flexibility**: Unified management for accounts, Auth Keys, subnet route approvals, visual + JSON ACL editing, and shared / VIP / user-managed DERP relays.

## Client Interoperability

Because Larktun preserves protocol compatibility on the control plane:

- You can point standard **Tailscale** clients (on Synology DSM, ASUSTOR, Linux, Windows, macOS, or iOS) directly to Larktun via `--login-server=https://hs.larktun.com`.
- Conversely, you can use the **Larktun iOS and Android apps** to log in to an existing Tailscale or self-hosted Headscale network using an auth key without migrating your servers.
