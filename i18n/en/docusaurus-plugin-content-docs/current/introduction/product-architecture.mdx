# Product Architecture

Larktun separates **control-plane coordination** from **encrypted data-plane transport** across four clean layers: SaaS control, tenant network control, relay fallback, and endpoint execution. This architecture delivers low-latency peer-to-peer connectivity whenever NAT permits, automatic relay fallback when networks are restrictive, and strict multi-tenant isolation by design.

## The Four Architecture Layers

| Layer | Primary Responsibilities | Operational Benefit |
|---|---|---|
| **1. SaaS Control Layer** | Account auth, tenant lifecycle, Auth Keys, quotas, and centralized audit log aggregation | Fast onboarding with no control servers or TLS certs to self-host |
| **2. Tenant Network Control Layer** | Per-tenant node registry, private IP allocation, subnet routes, MagicDNS, and ACL policy compilation | Zero cross-tenant state sharing and small blast radius |
| **3. Relay (DERP) Layer** | Encrypted TLS relay fallback when direct UDP traversal is blocked (shared, dedicated, or user-managed) | Reliable reachability across symmetric NAT and strict corporate firewalls |
| **4. Endpoint Execution Layer** | WireGuard tunnel setup, local ACL enforcement, path probing, and in-app `tsnet` runtime on mobile | Quiet, low-memory background operation and end-to-end encryption |

## How a Connection Flows End to End

When Device A connects to Device B (for example, your laptop SSHing into a cloud server or your iPad opening a home NAS):

1. **Authenticate & register**: Both endpoints authenticate to the control plane (`https://hs.larktun.com`) and exchange public WireGuard keys—private keys never leave the endpoint.
2. **Receive scoped netmap & ACLs**: The tenant control layer computes the minimal peer map allowed by the tenant's ACL document and pushes updates only to authorized peers.
3. **Attempt direct P2P path first**: Endpoints coordinate STUN/UDP hole punching to establish an encrypted WireGuard tunnel directly between peers, keeping latency minimal and bypassing relays entirely.
4. **Automatic DERP relay fallback**: If symmetric NAT or strict firewalls prevent direct UDP, encrypted WireGuard packets automatically traverse the tenant's configured DERP relay without dropping the session, and upgrade back to direct P2P automatically whenever network conditions allow.

## How Tenant Isolation Is Enforced

- **Dedicated network state per tenant**: Devices, users, IP address pools (`100.64.0.0/16` or custom ranges), routes, and MagicDNS namespaces are partitioned strictly by tenant.
- **No cross-tenant ACL references**: ACL compilation evaluates rules exclusively within one tenant boundary.
- **Isolated observability**: Audit records and device online/offline telemetry remain scoped per tenant for clean compliance reviews.

## Choosing Your Relay Strategy

- **Shared relay**: Included by default for free individual accounts, rapid testing, and lightweight remote access.
- **Dedicated relay**: Recommended for paid teams needing predictable latency and reserved capacity for RDP, WebRTC, or continuous operations.
- **User-managed relay**: Best for enterprises with data-residency requirements, private data-center egress boundaries, or custom regional POP placement (see [Deployment Modes and Configuration](../getting-started/install-and-configure)).
